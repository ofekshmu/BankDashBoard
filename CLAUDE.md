# BankDash — Claude Project Rules

## HTML Report Generation Architecture

The app generates monthly HTML analysis reports from two source files. **Always edit the sources, never the generated outputs.**

### Source files (ALWAYS edit these)

| File | Purpose |
|------|---------|
| `source/html/Base_template.html` | HTML skeleton with all CSS and static JS. Used by `generate_html()` as the base for every report. |
| `source/src_utils/utils.py` | Python code that programmatically builds HTML sections (transaction lists, KPI stat row, charts, etc.) and writes the final file. |
| `source/WebApp.py` → `_log_float_style()` / `_not_generated_html()` / `_splash_html()` | The regeneration-in-progress screen and the "no dashboard yet" screen. Edit here for any UI change to those pages. |

### Generated files (NEVER edit these directly)

| Path | What it is |
|------|-----------|
| `source/html/output.html` | Last-generated preview. **Overwritten on every analysis run.** Any edits are lost immediately. |
| `Outputs/general_analysis/*.html` | Cached monthly reports (e.g. `2026_05.html`). Regenerated by `POST /api/analysis`. Edits are silently discarded on next regeneration. |

### The rule

> If a CSS/JS/HTML change needs to appear in generated reports, it goes into **`Base_template.html`** (for static structure/styles) or **`utils.py`** (for programmatically-built sections like the KPI stat row). If it affects the regeneration screen, it goes into **`WebApp.py`**.
>
> **Never patch `source/html/output.html` or `Outputs/general_analysis/*.html`** — those changes will be lost the next time a user clicks "חשב מחדש".

### Why this went wrong before

Commits `eadd163`–`876c7ef` applied mobile CSS fixes by directly patching the pre-generated `*.html` files and `output.html`, treating them as the source of truth. When a month was regenerated, all those fixes silently disappeared. The fix was to backport everything into `Base_template.html` and `utils.py` (commits `78a6e8d`, `56d1796`).

## Database

- **Production:** Neon PostgreSQL — connection string in `.env` as `DATABASE_URL`. Table names are **all-lowercase** in PostgreSQL (e.g. `banktransactions`, not `BankTransactions`).
- **Local fallback:** SQLite at `ShmuelFamiliy.db` in the repo root.
- **`.env` must never be committed** — it is gitignored. It was accidentally committed once; the password must be rotated in the Neon console before any production deploy.
- `fill_missing.py` (repo root) is the idempotent SQLite → PostgreSQL gap-filler. Use per-row savepoints to avoid rolling back the entire transaction on FK violations.

## Deployment

- Active deployment branch: `deployment2_0` (branched from `main`).
- Vercel deployment: checks `os.getenv('VERCEL')` to decide between `/tmp/` and `Outputs/` paths.
- Do **not** run `ALTER TABLE` DDL on every request — it causes lock contention. Run it once at startup via `_run_acct_migrations()`.
